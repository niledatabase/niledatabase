Nile provides a cloud offering to help build multi-tenant apps. However, it is a lot easier to build and iterate
locally before using the cloud solution. Nile Docker provides all the tools required to build and test locally before
moving to the cloud solution.

The image is running all the extensions and components that Nile uses as part of our cloud offering except our global
control plane used to manage our customers and billing.

The Docker image includes:

- 3 Postgres instances, to emulate a distributed production-like setup
- Each Postgres instance has all the Nile extensions installed
- All functionalities documented in our docs work with the image
- At this point, the UI console is not included in the image

[Join our discord](https://discord.com/invite/8UuBB84tTy) to give feedback or ask questions about running and testing with Nile's Docker image.

## Using Nile's docker container with TestContainers

A common way to automate integration tests is using [TestContainers](https://testcontainers.org/).

The examples below use `ghcr.io/niledatabase/testingcontainer:latest`. For reproducible CI runs, replace this image reference
with a [published version tag](https://github.com/niledatabase/testingcontainer/releases) or an image digest
(`ghcr.io/niledatabase/testingcontainer@sha256:<digest>`). Update that reference when you choose to upgrade your test environment.

Both examples remove their containers and data after the test. Each run starts with a fresh database.

### Node.js

The following example shows how to use Nile's docker container with Node.js and
the [TestContainers](https://testcontainers.org/) library. It exposes a Postgres port and uses
`Wait.forLogMessage` strategy to wait until the container is ready. Then it connects to the database and runs a simple query.

Make sure you install `testcontainers` and `pg` npm packages:

```bash
npm install testcontainers pg
```

and then you can run the following snippet:

```typescript
import { GenericContainer, Wait } from 'testcontainers';
import pg from 'pg';

const image = 'ghcr.io/niledatabase/testingcontainer:latest';
const container = await new GenericContainer(image)
  .withExposedPorts(5432)
  .withWaitStrategy(
    Wait.forLogMessage('Database has been created and is ready'),
  )
  .start();

const client = new pg.Client({
  host: container.getHost(),
  port: container.getMappedPort(5432),
  user: '00000000-0000-0000-0000-000000000000',
  password: 'password',
  database: 'test',
});
try {
  await client.connect();
  const res = await client.query('SELECT version()');
  console.log(res.rows[0]);
} finally {
  try {
    await client.end();
  } finally {
    await container.stop();
  }
}
```

Troubleshooting tip:

- You can get the containter logs while tests are running by running `export DEBUG=testcontainers*` before running the tests.

### Python

Make sure you install `testcontainers` and `psycopg` python packages:

```bash
pip install testcontainers "psycopg[binary]"
```

and then you can run the following snippet:

```python
from testcontainers.core.container import DockerContainer
from testcontainers.core.wait_strategies import LogMessageWaitStrategy
import psycopg

with (
    DockerContainer("ghcr.io/niledatabase/testingcontainer:latest")
    .with_exposed_ports(5432)
    .waiting_for(LogMessageWaitStrategy("Database has been created and is ready"))
) as container:
    with psycopg.connect(
        host=container.get_container_host_ip(),
        port=container.get_exposed_port(5432),
        user="00000000-0000-0000-0000-000000000000",
        password="password",
        dbname="test",
    ) as client:
        with client.cursor() as cursor:
            cursor.execute("SELECT version()")
            print(cursor.fetchone())
```

Troubleshooting tip:

- On MacOS, you may need to explicitly set the `DOCKER_HOST` environment variable:

```bash
export DOCKER_HOST=unix:///Users/<your username>/.docker/run/docker.sock
```

## Configuring email for local tests

Email-based authentication flows, such as invitations and password resets, need an SMTP server configured in `auth.email_servers`.
For local tests, you can use an email capture service such as [Mailpit](https://mailpit.axllent.org/docs/install/docker/).
It runs separately from the Nile container and lets you inspect messages without delivering them to real inboxes.

For example, with a Mailpit container named `mailpit` on the same Docker network as Nile, connect to your test database and run:

```sql
INSERT INTO auth.email_servers (name, server)
VALUES ('local', 'smtp://mailpit:1025');
```

Use a hostname reachable from the Nile container; `localhost` refers to the Nile container itself.
Expose Nile's port 3000 when testing the auth API. SMTP configuration is not needed for SQL-only tests.
